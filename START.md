# Запуск на macOS с нуля

Инструкция рассчитана на чистый Mac. Ничего, кроме браузера и Терминала,
заранее знать не нужно.

Читается сверху вниз. После каждого шага написано, **что вы должны увидеть**, —
если увидели другое, смотрите раздел «Когда что-то пошло не так» в конце.

---

## Шаг 0. Открыть Терминал

`Cmd + Пробел` → наберите `Терминал` → Enter.

Всё, что ниже, набирается в этом окне. Команда выполняется по Enter.

---

## Шаг 1. Проверить Python

```bash
python3 --version
```

Нужно **3.11 или новее**. Ожидаемый ответ вроде `Python 3.11.7`.

Если ответ `command not found` или версия ниже 3.11 — поставьте Python
с [python.org/downloads](https://www.python.org/downloads/) (кнопка
«Download for macOS», обычный установщик .pkg). После установки закройте
и заново откройте Терминал.

> Системный Python в macOS иногда старый и трогать его не надо. Установщик
> с python.org ставит свой рядом и ничего не ломает.

---

## Шаг 2. Скачать код

```bash
cd ~
git clone https://github.com/nutakoe27-commits/threads-ai-copilot.git
cd threads-ai-copilot
```

Если `git` не установлен, macOS сама предложит поставить Command Line Tools —
согласитесь, это займёт пару минут, потом повторите команду.

**Проверка:** команда `ls` должна показать `run.py`, `src`, `config`.

Дальше все команды выполняются **из этой папки**. Если открыли новое окно
Терминала — сначала `cd ~/threads-ai-copilot`.

---

## Шаг 3. Создать окружение и поставить зависимости

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Первая команда создаёт отдельную папку с библиотеками внутри проекта —
чтобы ничего не ставилось в систему целиком. Вторая её включает: в начале
строки Терминала появится `(.venv)`. Третья ставит три библиотеки:
`requests`, `PyYAML`, `anthropic`.

**Проверка:** в начале строки видно `(.venv)`, а `pip install` закончился
строкой `Successfully installed ...`.

> `(.venv)` пропадает при закрытии Терминала. В новом окне снова
> `cd ~/threads-ai-copilot && source .venv/bin/activate`. Забыли — увидите
> `ModuleNotFoundError: No module named 'yaml'`, это и есть признак.

---

## Шаг 4. Прописать ключи

```bash
cp .env.example .env
open -e .env
```

Откроется TextEdit. Заполните строки после `=`, **без кавычек и без пробелов**:

| Переменная | Обязательна | Где взять |
|---|---|---|
| `ANTHROPIC_API_KEY` | да | [console.anthropic.com](https://console.anthropic.com) → API Keys |
| `CHECKO_API_KEY` | да | [checko.ru](https://checko.ru) → личный кабинет. Бесплатно 100 запросов в сутки |
| `TELEGRAM_BOT_TOKEN` | нет | напишите [@BotFather](https://t.me/BotFather) → `/newbot` |
| `TELEGRAM_CHAT_ID` | нет | напишите [@userinfobot](https://t.me/userinfobot), он ответит числом |
| `PERPLEXITY_API_KEY` | нет | в конвейере не используется, нужен только для зонда |

Должно получиться так:

```
ANTHROPIC_API_KEY=sk-ant-api03-xxxxxxxx
CHECKO_API_KEY=abcdef123456
```

Сохраните (`Cmd + S`) и закройте.

**Телеграм можно пропустить.** Без него список просто не улетит в мессенджер,
он всё равно будет лежать файлом и в панели.

> **Ключи в файл, не в код.** `.env` в git не попадает — это прописано
> в `.gitignore`. Никогда не вставляйте ключ прямо в команду или в код:
> он останется в истории Терминала и в истории репозитория навсегда.

---

## Шаг 5. Проверить, что всё собралось

```bash
python3 selftest.py
```

Это офлайн-проверка: в интернет она не ходит, денег не тратит, ключи ей
не нужны. Проверяет разбор ответов API, фильтры, сверку фактов, промпты,
воронку, статусы, панель — всё на подставных данных.

**Проверка:** последняя строка — `Все проверки пройдены.`

Если что-то провалилось — там будет список названий. Это значит, что чинить
надо до первого боевого прогона, а не после.

> Эту команду полезно запускать после каждой правки конфигов. Она уже ловила
> реальные ошибки: конфликт стоп-слова «водитель» внутри «руководитель отдела
> продаж», и письма, которые молча писала дешёвая модель вместо сильной.

## Шаг 6. Открыть панель

```bash
python3 run.py --stage ui
```

Откройте в браузере **http://127.0.0.1:8765**

Дальше всё делается отсюда, терминал больше не нужен. Пять вкладок:

**Прогон** — кнопки этапов. Сверху вниз — это и есть порядок ежедневной
работы. Во время прогона видно полосу выполнения, на какой компании
сейчас стоим, и живой лог. Рядом кнопка «остановить»: прогон прервётся
на следующей компании, не посреди записи.

У каждого этапа есть вторая кнопка — **«проба»**. Она делает всё, кроме
записи: удобно проверить настройки, не тратя дневной запас запросов.

**Письма** — всё готовое к отправке, отсортированное по баллу схождения
сигналов. Кнопка «копировать письмо», кнопки статусов: отправлено,
ответили, договорились, просили не писать.

**Отправленные** — что уже ушло, с фильтром по статусу и долей ответов.
Текст каждого письма раскрывается по клику. Отсюда же можно отметить, что
человек ответил.

**Воронка** — сколько компаний прошло каждый этап, конверсии, и отдельно
красный блок, если конверсия за неделю упала вдвое.

**Настройки** — критерии отбора, веса баллов, лимиты и тексты писем.
Главный файл здесь — **«Шаблон письма»**: это само письмо, всё в нём, кроме
мест в фигурных скобках, уходит адресату дословно.
Сломанный файл не сохранится: панель проверит его перед записью и скажет,
в какой строке ошибка. Прежняя версия уходит в копию, вернуть её — кнопка
с датой внизу страницы.

Ключи API отсюда не правятся и не показываются — они в `.env`, и это
намеренно.

**Логи** — последние 300 записей с фильтром по уровню и этапу.
Страница обновляется сама раз в 10 секунд.

Остановить панель — `Ctrl + C` в Терминале.

> Панель слушает только `127.0.0.1`, то есть доступна с этого компьютера
> и больше ниоткуда. Это намеренно: отсюда запускаются прогоны и правятся
> настройки, а пароля у панели нет — он и не нужен, пока её не видно снаружи.

## Шаг 7. Первый прогон

На вкладке **Прогон** нажмите четыре кнопки по очереди. Каждую — после
того, как предыдущая закончилась.

**1. Найти компании** (2–5 минут). Система ищет в Checko компании по отрасли
и региону из настроек, берёт карточку и финансы, выносит вердикт: подходит
или нет, с причиной человеческим языком.

Упёрлись в 100 запросов? Не ошибка: прогресс в базе, завтра та же кнопка
продолжит с того места, где остановилась.

**2. Обойти сайты** (3–8 минут). Для прошедших отбор открывается сайт,
читаются несколько страниц плюс страница вакансий, собираются факты.
Каждый факт подтверждается цитатой со страницы — что не подтвердилось,
в досье не попадает.

Система соблюдает `robots.txt`, ходит с паузой в две секунды и честно
представляется. Паузу меньше секунды панель поставить не даст.

**3. Написать письма** (2–6 минут). Письмо собирается из шаблона: модель
пишет только вопрос в первом абзаце и перечень признаков покупателя.
Потом код **без модели** проверяет, попали ли факты из досье в текст.
Письмо, которое ни на что не опирается, откладывается.

Итог вида «написано 6, отложено 3, пропущено по рейтингу 12» — нормально.
Отложенные защищают от общих писем, пропущенные — от траты дорогой модели
на компании, у которых не сошлось ни одного признака. Порог рейтинга —
в «Настройках», строка `min_score`.

**4. Собрать утренний список** (секунды). Файл в `morning/` и, если
подключён Телеграм, сообщение туда.

Готово: идите на вкладку **Письма**.

## Шаг 8. Ежедневный ритм

Один раз утром:

```bash
cd ~/threads-ai-copilot && source .venv/bin/activate
python3 run.py --stage ui
```

Дальше в браузере, на вкладке **Прогон**: «Найти компании» → «Обойти сайты» →
«Написать письма» → «Написать дожимы» → «Собрать утренний список».

Потом на вкладке **Письма**: читаете, копируете кнопкой, отправляете
**из своего ящика руками**, жмёте «отправлено». Система сама писем не шлёт.

**Если поправили тексты писем** на вкладке «Настройки» — нажмите
**«Переписать письма заново»**. Правка промпта не меняет письма, которые уже
лежат в базе готовым текстом; эта кнопка стирает неотправленные и пишет их
заново по новым правилам. Отправленные она не трогает: их текст уже
у адресата.

Раз в неделю загляните на вкладку **Воронка**.

Раз в месяц: скачайте выгрузки реестров Минцифры в `data/registries/`
и нажмите «Импорт реестров», потом «Пересчитать баллы». Что именно скачивать,
скажет сама кнопка, если файлов нет.

**Если панель удобнее держать всегда открытой** — оставьте её работать
в отдельной вкладке Терминала. Она ничего не делает, пока не нажать кнопку.

## Шаг 9. Автозапуск (когда ритм устоится)

Не делайте этого в первую неделю. Сначала нужно своими глазами увидеть,
что прогон даёт нормальный результат.

```bash
crontab -e
```

Откроется редактор `vi`. Нажмите `i`, вставьте строку, потом `Esc`,
затем `:wq` и Enter.

```cron
0 7 * * 1-5 cd $HOME/threads-ai-copilot && .venv/bin/python run.py --stage targets && .venv/bin/python run.py --stage dossier && .venv/bin/python run.py --stage compose && .venv/bin/python run.py --stage morning >> logs/cron.log 2>&1
```

По будням в 07:00. Ноутбук должен быть включён и не спать — иначе задание
просто пропустится. Если это неудобно, оставьте ручной запуск: это четыре
кнопки в панели.

Коды возврата: `0` — всё хорошо, `2` — были ошибки, `1` — падение.
Двойка заставит cron прислать письмо, а «сегодня новых компаний нет»
письма не вызовет.

## Когда что-то пошло не так

**`command not found: python3`**
Python не установлен или Терминал не перезапущен после установки.
Закройте окно, откройте заново, повторите.

**`ModuleNotFoundError: No module named 'yaml'` (или `requests`, `anthropic`)**
Забыли включить окружение: `source .venv/bin/activate`. В начале строки
должно появиться `(.venv)`.

**`error: externally-managed-environment` при `pip install`**
Вы ставите не в окружение, а в систему. Это как раз то, от чего защищает
шаг 3: сделайте `python3 -m venv .venv && source .venv/bin/activate`
и повторите `pip install`.

**`SSL: CERTIFICATE_VERIFY_FAILED`**
Свежий Python с python.org требует один раз установить сертификаты.
В Finder: `Программы` → `Python 3.11` → двойной клик по
`Install Certificates.command`.

**`Address already in use` при запуске панели**
Панель уже работает в другой вкладке Терминала. Найдите её или закройте
процесс: `pkill -f "stage ui"`.

**`Не задан ANTHROPIC_API_KEY`** (или `CHECKO_API_KEY`)
Файл называется ровно `.env` (не `.env.txt` — TextEdit любит дописывать
расширение) и лежит в корне проекта. Проверить: `cat .env`.

**`Достигнут дневной лимит Checko`**
Это не ошибка. Бесплатный тариф — 100 запросов в сутки, прогресс сохранён,
завтра продолжится с того же места.

**Утренний список пустой**
Либо все компании уже показаны раньше (нормально), либо ни одна не прошла
отбор. Второе видно на вкладке «Воронка». Что делать — в `RUNBOOK.md`.

**Письма получаются общими, «ни о чём»**
Смотрите отложенные: `sqlite3 data/leads.db < tools/thin.sql`. Скорее всего,
сайт компании не дал фактов. Порог фактов правится на вкладке «Настройки»,
файл «Критерии отбора», строка `min_facts` — но опускать его значит
соглашаться на слабые письма.

**Кнопка в панели говорит «Уже идёт другой прогон»**
Так и есть: прогон идёт один за раз, потому что все этапы пишут в одну базу
и тратят один общий запас запросов. Дождитесь конца или нажмите «остановить».

**Нажал «остановить», а прогон продолжается**
Он остановится на следующей компании. Убивать поток посреди записи нельзя —
база осталась бы в непонятном состоянии. Если этап короткий (сборка списка,
пересчёт баллов), он просто успеет закончиться.

**Панель не сохраняет настройки**
Прочитайте красную строку под кнопкой — там сказано, что именно не так:
сломанный YAML с номером строки или нарушение защиты. Файл на диске при этом
не тронут, старая версия на месте.

**Что-то другое**
Полный лог за день: `open logs/$(date +%F).log`. Шесть сценариев поломок
разобраны в `RUNBOOK.md`.

## Чего система не делает

- **Не отправляет письма.** Готовит текст, отправляете вы, из своего ящика.
- **Не хранит имена людей.** Только реквизиты юрлица и обезличенные адреса
  вида `info@`, `sales@`. Имя адресата подставляете руками.
- **Не ходит туда, где это запрещено.** `robots.txt` соблюдается,
  hh.ru автоматически не читается — в списке есть ссылка, которую вы
  открываете сами.
- **Не пишет тем, кто отказался.** Отказ уходит в `data/stoplist.txt` навсегда.
