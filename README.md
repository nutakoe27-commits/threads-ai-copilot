# GTM-система: утренний список лидов

Этап 1 — «Утренний список v0». Собирает сигналы о боли в лидгене из открытых
данных «Работы России», отбирает подходящие компании и складывает утренний
список в `morning/YYYY-MM-DD.md`.

Полная архитектура — в [PLAN.md](PLAN.md). Обоснование решений — в
[DECISIONS.md](DECISIONS.md).

## Состояние на 2026-07-26

Событийный сигнал («компания прямо сейчас ищет продажника») пока недоступен:
trudvsem не содержит нужный ICP, hh.ru закрыл анонимный доступ. Подробности —
в [DECISIONS.md](DECISIONS.md), записи Р-014 и Р-016.

Поэтому сейчас строится **целевой список по критериям ICP** через Checko, а
поводом для письма служат факты о компании: профиль, размер и динамика
выручки. Событийные сигналы добавятся, когда найдётся рабочий источник
(Р-017). Код сбора сигналов и утреннего списка при этом рабочий и
переиспользуется — менять нужно только модуль-источник.

## Установка

```bash
git clone <репозиторий> && cd threads-ai-copilot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Ключи API на Этапе 1 не нужны — источник бесплатный и без авторизации.
`.env` понадобится начиная с Этапа 2 (шаблон — в `.env.example`).

## Этап 2: целевой список через Checko

### Что нужно

Ключ Checko. Регистрация на [checko.ru](https://checko.ru) даёт **100 запросов
в сутки бесплатно** — этого хватит на первую сборку. Положите в `.env`:

```
CHECKO_API_KEY=ваш_ключ
```

### Шаг 1. Зонд — потратить 2 запроса и увидеть настоящий ответ

```bash
python probe_checko.py
```

Покажет сырой JSON поиска и карточки компании, а затем — что из этого извлёк
наш разбор. Если какие-то поля остались пустыми, скрипт прямо скажет, какие
именно и куда дописать их реальные имена.

Это обязательный шаг, а не формальность: структуру ответа Checko я не
проверял, разбор написан «вслепую», но защитно. У trudvsem похожая слепая
догадка про параметр `offset` стоила целого прогона.

### Шаг 2. Построить список

```bash
python run.py --stage discover     # поиск кандидатов по ОКВЭД и регионам
python run.py --stage enrich       # карточка по каждому + вердикт ICP
python run.py --stage targets      # то же самое одной командой
```

Оба прохода **возобновляемые**. Упёрлись в суточные 100 запросов — прогресс
в базе, завтра продолжится с того же места. Ничего не запрашивается повторно.

В конце будет сводка: сколько компаний прошло ICP, сколько отсеяно. У каждой
отсеянной в базе записана причина человеческим языком — можно посмотреть,
не смягчить ли критерий, не тратя запросы заново:

```bash
sqlite3 data/leads.db \
  "SELECT name, icp_reason FROM companies WHERE icp_status='rejected' LIMIT 20"
```

### Что настраивается

`config/icp.yaml`: коды ОКВЭД, регионы, границы штата и выручки, минимальный
возраст, исключённые ОКВЭД, суточный бюджет запросов.

## Этап 1: сбор сигналов (источник сейчас не выбран)



### 1. Разведочный прогон и настройка отраслевого фильтра

```bash
python run.py --stage collect --dry-run
```

Ничего не пишет, но проходит все страницы. Займёт несколько минут: только по
Москве около 30 страниц.

**Смотрите в конец лога — там две таблицы.**

«Отрасли среди совпавших вакансий» показывает реальные названия отраслей из
классификатора trudvsem. Скопируйте подходящие в `filters.specialisation_include`
в `config/signals.yaml` — это бесплатно отсечёт розницу, банки и медицину ещё
до платных запросов в Checko на Этапе 2.

«Сработавшие ключевые слова» показывает, какое слово сколько совпадений дало.
Если какое-то тащит мусор — правьте его в том же файле.

Отдельные компании-спамеры (розничные сети публикуют сотни вакансий) заносите
по ИНН в `data/stoplist.txt`.

### 2. Боевой прогон

```bash
python run.py
```

Результат — `morning/YYYY-MM-DD.md`. Компании с сильными сигналами (в вакансии
прямым текстом «холодные звонки», «поиск новых клиентов») идут первыми и
помечены 🔥.

### 3. Проверить дедупликацию

Запустите ту же команду ещё раз. Второй прогон **не должен добавить ни одной
компании** — все уже показаны. В логе будет «Новых компаний нет».

## Как понять, что этап удался

Главный вопрос Этапа 1 — **хватает ли покрытия «Работы России» под ваш ICP**.
Это неизвестный параметр, и он проверяется здесь, а не догадками.

| Результат за прогон | Вывод |
|---|---|
| ≥5 релевантных IT-аутсорс-компаний | Источник работает, идём на Этап 2 |
| 2–4 | Пограничный случай — расширить регионы или ключевые слова |
| 0–1 несколько дней подряд | Источник не покрывает ICP. **Стоп**, возвращаемся к выбору источников, а не строим дальше |

«Релевантная» = похоже на IT-аутсорс/веб-студию/интегратора со штатом
примерно 15–100. Автоматической проверки ICP на Этапе 1 ещё нет — она
появится на Этапе 2 через Checko.

## Команды

```bash
python run.py                        # полный прогон: сбор + отчёт
python run.py --stage collect        # только сбор
python run.py --stage report         # только пересобрать отчёт
python run.py --dry-run              # ничего не записывать
python run.py --stage collect --raw  # показать сырой ответ API
python run.py --verbose              # подробный лог
python selftest.py                   # проверить логику без обращения к сети
```

Имена полей API уже сверены с боевым ответом 2026-07-26 и совпадают
(`job-name`, `duty`, `vac_url`, `creation-date`, `company.inn`,
`category.specialisation`). `--raw` нужен, только если API изменится.

**`python selftest.py` стоит запускать после каждой правки
`config/signals.yaml`** — он ловит конфликты между ключевыми и стоп-словами.
Такой конфликт уже был: стоп-слово «водитель» находилось внутри
«рукоVODITEЛЬ отдела продаж» и молча выбрасывало вакансии РОПа.

Коды возврата: `0` — всё хорошо, `2` — были ошибки (например, источник
недоступен), `1` — необработанное падение.

## Автозапуск

```bash
crontab -e
```

```cron
0 6 * * 1-5 cd /path/to/threads-ai-copilot && .venv/bin/python run.py >> logs/cron.log 2>&1
```

По будням в 06:00. Код возврата `2` заставит cron прислать письмо, если
источник отвалится — «сегодня пусто» письма не вызовет.

## Что настраивается без правки кода

`config/signals.yaml`:

- `keywords.strong` — фразы, по которым компания попадает в список с высоким
  приоритетом;
- `keywords.normal` — должности, по которым берём с обычным приоритетом;
- `keywords.exclude_job` — стоп-слова в названии должности (розница, B2C, HR);
- `regions` — регионы и их коды;
- `filters.company_cooldown_days` — сколько дней не показывать компанию повторно;
- `source.lookback_days` — за сколько дней смотреть вакансии.

`data/stoplist.txt` — ИНН компаний, которым больше не пишем. Правило вечное:
отказался — больше никогда.

## Границы: чего система не делает

- Не ходит в hh.ru автоматически. В отчёте есть ссылка на поиск по hh —
  вы открываете её сами. Причина в [DECISIONS.md, Р-001](DECISIONS.md).
- Не хранит персональные данные: только реквизиты юрлица и обезличенные
  корпоративные адреса. Имя ЛПР подставляете руками при отправке (Р-000).
- Не отправляет письма. Отправка появится на Этапе 5, и тоже по одному,
  с ручным просмотром (Р-007).
